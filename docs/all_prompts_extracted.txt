How to use this playbook
This is not one giant prompt. It is a controlled build sequence. Each prompt gives Antigravity a bounded task, expected
outputs, and completion checks.
●
 Start from an empty project folder. Open that folder in Antigravity and allow it to inspect the workspace.
●
 Paste only one prompt at a time. Wait for Antigravity to finish, review the files, run the app, and verify the acceptance
checks.
●
 Do not skip the PayPal sandbox milestone. The hackathon requires a meaningful, working PayPal integration and
meaningful AI use.
●
 Do not claim sponsor integrations before using them. AG Grid, Render, Postman, APIMatic, Bryntum, and Zapier
should be selected on Devpost only if they are genuinely integrated or used as required by the rules.
●
 Keep secrets out of source control. Use .env locally, .env.example for placeholders, and deployment secret settings
in Render.
●
 Use sandbox data only. Never process real money or store card details.
●
 Keep the MVP narrow. Complete one invoice-to-payment workflow end-to-end before optional features.

creation/send → webhook/status synchronization → receivables dashboard.
●
 AI may propose and prepare actions. Backend policy checks and explicit user approval authorize sensitive operations.
●
 The LLM must never receive PayPal client secrets, database credentials, or unrestricted database access.
●
 All money amounts use decimal-safe handling (Decimal in Python); never use binary floating-point for financial
calculations.
●
 Store currency explicitly. Do not assume all customers use USD.
●

deliveries idempotently.

 Do not fabricate payment success. Only verified PayPal API responses or verified webhook events can update
payment state.
